# 页面结构与功能排列规范

> 本文档固化 WebUI 全部页面的展示顺序、每页功能项及排列逻辑，作为后续开发与验收的依据。
> 最近一次梳理：2026-10-24（新增「地图」页后复核）。

## 一、整体组织原则

侧边栏页面顺序按「**使用频率 + 监控 → 操作 → 管理 → 配置**」四层原则排列：

1. **监控层（高频，随时看）**：仪表板是默认落地页，集中所有「看」的功能（状态、图表）与最高频的「做」（连接控制）；
   地图同属监控层（看机器人位置、周边地形、当前路径），且是「看 + 立刻操作」（点击寻路）的页面，紧随仪表板。
2. **运维层（中高频，排查时用）**：终端日志是只读的排查工具，位于监控层之后。
3. **管理层（中频，定期操作）**：白名单属于访问控制类写操作。
4. **配置层（低频，调整时用）**：两个配置页按「日常调优 → 部署期设置」递减频率排列。

原则取舍说明：基础配置（服务器地址、账号等）虽在部署流程中「最先设置」，但设置后极少再动，按**频率优先**原则置于最后，与主流管理面板（路由器/服务器管理页）的「设置殿后」惯例一致。

## 二、页面展示顺序总览

| # | 页面 | 导航名 | 层级 | 数据接口 |
|---|------|--------|------|----------|
| 1 | `#dashboard` | 仪表板 | 监控 | GET /api/dashboard (+SSE 流) |
| 2 | `#map` | 地图 | 监控 | /api/map/tile, /api/map/state (1Hz 轮询), POST /api/map/path, /api/map/stop |
| 3 | `#terminal` | 终端日志 | 运维 | /api/logs/stream (SSE) + /api/commands |
| 4 | `#players` | 白名单管理 | 管理 | /api/whitelist |
| 5 | `#features` | 功能配置 | 配置 | GET/POST /api/features |
| 6 | `#basic` | 基础配置 | 配置 | GET/POST /api/basic |

## 三、每页功能项及排列逻辑

### 1. 仪表板（#dashboard）

自上而下：
1. **控制块**（连接 / 断开 / 重连 / 关闭）——四宫格快捷操作，按「操作强度递增」排列（连接最常用放最左，关闭代理最危险放最右）。
2. **状态卡片**（8 个）——按「整体 → 细节」排列：代理状态 → 机器人账号 → 代理地址 → 运行时间 → 玩家连接 → 队列 → 血量/饱食度 → MC 版本。
3. **监控图表**（4 个）——按资源类型排列：CPU → 内存 → 网络流量 → 延迟波动（含玩家延迟明细）。

### 2. 地图（#map）

左「图」右「数」两栏，符合「先看位置、再看数值」：

1. **地图卡片**（左）——标题栏含缩放／回到机器人／刷新四个图标按钮；画布占满卡片，叠加坐标网格与刻度、光标实时坐标。
   点击画布任意点即让机器人寻路过去，路径分「已走过（淡）／剩余（亮）」两段绘制，分段终点到目标之间用虚线补全。
2. **坐标面板**（右）——自上而下：机器人坐标（X/Y/Z，等宽字体突出）+ 朝向 → 目标坐标 + 直线距离 + 路径剩余
   → 寻路状态（空闲／计算路径中／寻路中／已到达／寻路失败／未连接）→ 停止寻路按钮（仅在寻路中可点）。
3. 未加载区块保持透明并显示深色底，机器人未连接时整图覆盖「无数据」提示。

### 3. 终端日志（#terminal）

1. 标题栏（会话用户、连接状态、命令/日志计数、导出、清空）。
2. 日志输出区（SSE 实时流 + 历史缓冲）。
3. 命令输入行（Tab 补全、历史上下翻）。

### 4. 白名单管理（#players）

自上而下按「配置 → 操作 → 结果」：
1. 配置区：启用白名单开关 → 自动添加机器人账户开关 → 踢出消息（手动保存）。
2. 添加区：玩家名输入 + 添加按钮。
3. 列表区：白名单条目（名称 / UUID / 移除按钮）。

### 5. 功能配置（#features）

1. **分类筛选 chips**——顺序与后端 GROUPS 一致：战斗 → 生存 → 移动/防挂机 → 连接 → 聊天 → 告警 → 防护 → 自动化 → 其他；首项「全部」带总数。
2. **分组区块**——每个分组一张强调条标题 + 卡片双列区；筛选时仅显示命中分组。
3. **功能卡片**（每分组内左右两列交替分配，列间解耦）——带参数的卡片默认折叠，标题栏含展开箭头 + master 开关；无参数卡片为静态标题。所有改动即时保存（350ms 防抖，无提示弹窗）。

### 6. 基础配置（#basic）

与功能配置完全独立（独立 API、独立 handler：FeatureHandler 锚定 `CONFIG.client.extra`，BasicConfigHandler 锚定 CONFIG 根）。分组按「连接链路」排列：

1. **目标服务器**——服务器地址、端口（先定「连谁」）。
2. **账号认证**——登录方式（MSA/DEVICE_CODE/…/OFFLINE 枚举）、账号用户名、离线 UUID（再定「用谁连」）。
3. **连接与心跳**——启动时自动连接、心跳间隔、心跳超时、KeepAlive 模式与超时、连接超时（后定「怎么保活」）。
4. **代理监听**——监听地址、端口（最后定「玩家怎么连进来」）。

所有改动即时保存（350ms 防抖，无提示弹窗）；写入路径白名单校验，非法路径被拒绝。

## 四、验收要点

- [ ] 侧边栏顺序：仪表板 → 地图 → 终端日志 → 白名单管理 → 功能配置 → 基础配置。
- [ ] 新增页面时须归入上述四层之一，并按层内频率插入；不得打乱既有相对顺序。
- [ ] 功能配置与基础配置互相独立：API 分离（/api/features、/api/basic），页面分离，任何一侧的样式/逻辑改动不得影响另一侧。
- [ ] 配置类页面统一「即时保存、无弹窗」交互；白名单踢出消息保留手动保存。
- [ ] 全站视觉为扁平直角风格：任何新组件不得使用 `border-radius`。
